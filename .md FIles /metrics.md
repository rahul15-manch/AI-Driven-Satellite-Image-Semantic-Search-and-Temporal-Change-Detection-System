## 1. Cross-Modal Semantic Retrieval Metrics

### 1.1 Mathematical Formulation of Retrieval
Let the evaluation collection consist of $N$ image scenes $\{I_1, I_2, \dots, I_N\}$ with corresponding feature embeddings $\mathbf{V} = [\mathbf{v}_1, \dots, \mathbf{v}_N] \in \mathbb{R}^{N \times D}$, where $\|\mathbf{v}_i\|_2 = 1.0$.

Given a natural language text query $q$, the text encoder generates a normalized embedding $\mathbf{u}_q \in \mathbb{R}^D$ where $\|\mathbf{u}_q\|_2 = 1.0$.

The similarity vector $\mathbf{s}_q \in [-1, 1]^N$ is computed via inner product:
$$s_q(i) = \langle \mathbf{u}_q, \mathbf{v}_i \rangle = \sum_{d=1}^D u_{q, d} \cdot v_{i, d}$$

The candidate gallery is sorted in descending order of similarity to produce a permutation ranking:
$$\pi_q = (\pi_q(1), \pi_q(2), \dots, \pi_q(N)) \quad \text{such that} \quad s_q(\pi_q(1)) \ge s_q(\pi_q(2)) \ge \dots \ge s_q(\pi_q(N))$$

The rank of a specific image $I^*$ for query $q$ is defined as:
$$\text{rank}_q(I^*) = \min \{ r \in \{1, \dots, N\} \mid \pi_q(r) = I^* \}$$

---

### 1.2 Ground-Truth Relevance Definitions for RSICD

RSICD contains 10,921 images, each associated with 5 captions. On the held-out test split of 1,093 images, there are exactly $5 \times 1,093 = 5,465$ test queries `[LOCALLY MEASURED]`.

#### Protocol 1: Caption-to-Own-Image (Instance Retrieval) — Primary Benchmark
- **Relevance Rule:** A query caption $q_{i, k}$ ($k \in \{1, \dots, 5\}$) has exactly ONE relevant ground-truth image: $I_i$.
$$\text{Rel}(q_{i, k}, I_j) = \begin{cases} 1 & \text{if } j = i \\ 0 & \text{if } j \ne i \end{cases}$$
- This directly matches the standardized benchmark protocol of Lu et al. (2018) and Liu et al. (2024).

#### Protocol 2: Category-Level Relevance (Semantic Class Retrieval) — Secondary Benchmark
- **Relevance Rule:** For user-facing category queries (e.g., *"airport"* or *"storage tank"*), an image $I_j$ is relevant if its annotated scene class matches the query class:
$$\text{Rel}_{\text{cat}}(q, I_j) = \begin{cases} 1 & \text{if } \text{Class}(I_j) = \text{Class}(q) \\ 0 & \text{otherwise} \end{cases}$$

### 1.3 Retrieval Performance Metrics

#### 1. Recall@K ($R@K$, $K \in \{1, 5, 10\}$)
The proportion of queries for which the target ground-truth image is retrieved within the top-$K$ ranked positions:
$$R@K = \frac{1}{|Q|} \sum_{q \in Q} \mathbb{I}[\text{rank}_q(I_q^*) \le K]$$
Where:
- $|Q| = 5,465$ (the total number of test queries in RSICD).
- $\mathbb{I}[\cdot]$ is the indicator function ($\mathbb{I}[\text{True}] = 1, \mathbb{I}[\text{False}] = 0$).
- $R@1$ measures exact top-1 accuracy.
- $R@5$ and $R@10$ measure presence in common UI display windows.

#### 2. Mean Reciprocal Rank (MRR)
Measures the average multiplicative inverse of the rank of the first relevant image:
$$\text{MRR} = \frac{1}{|Q|} \sum_{q \in Q} \frac{1}{\text{rank}_q(I_q^*)}$$
- If the true image is ranked 1st, reciprocal rank is $1.0$.
- If ranked 2nd, reciprocal rank is $0.5$.
- If ranked 10th, reciprocal rank is $0.1$.
- Range: $(0, 1]$, where higher is superior.

#### 3. Precision@K ($P@K$, for Category Queries)
For multi-relevant category queries with $|R_q|$ relevant items in the gallery:
$$P@K = \frac{1}{K} \sum_{r=1}^K \text{Rel}(q, \pi_q(r))$$

## 2. Bi-Temporal Change Detection Metrics

### 2.1 Confusion Matrix Formulation
Let $Y \in \{0, 1\}^{H \times W}$ denote the binary ground-truth change mask ($1 = \text{Change}, 0 = \text{No-Change}$), and let $\hat{Y} \in \{0, 1\}^{H \times W}$ denote the binary predicted change mask generated by thresholding a continuous change score surface $D \in [0, 1]^{H \times W}$ at threshold $\tau$:
$$\hat{Y}(x, y) = \mathbb{I}[D(x, y) \ge \tau]$$

Across all pixels $(x, y) \in \Omega$ of all evaluated test scenes, the cumulative confusion counts are defined as:
$$\text{True Positives (TP)} = \sum_{x, y} \mathbb{I}[Y(x, y) = 1 \land \hat{Y}(x, y) = 1]$$
$$\text{False Positives (FP)} = \sum_{x, y} \mathbb{I}[Y(x, y) = 0 \land \hat{Y}(x, y) = 1] \quad (\text{False Alarms})$$
$$\text{False Negatives (FN)} = \sum_{x, y} \mathbb{I}[Y(x, y) = 1 \land \hat{Y}(x, y) = 0] \quad (\text{Missed Changes})$$
$$\text{True Negatives (TN)} = \sum_{x, y} \mathbb{I}[Y(x, y) = 0 \land \hat{Y}(x, y) = 0]$$

---

### 2.2 Primary Change Detection Metrics

#### 1. Precision ($P$)
Fraction of detected change pixels that correspond to actual ground change:
$$P = \frac{\text{TP}}{\text{TP} + \text{FP}}$$
- Operational note: If $\text{TP} + \text{FP} = 0$ (detector predicts zero change anywhere), define $P = 0.0$.

#### 2. Recall ($R$)
Fraction of actual ground change pixels successfully detected:
$$R = \frac{\text{TP}}{\text{TP} + \text{FN}}$$
- Operational note: If $\text{TP} + \text{FN} = 0$ (scene contains no ground change), define $R = 1.0$ if $\text{FP} = 0$, else $0.0$.

#### 3. F1-Score ($F_1$) on Changed Class — Primary Metric
The harmonic mean of precision and recall:
$$F_1 = 2 \cdot \frac{P \cdot R}{P + R} = \frac{2 \cdot \text{TP}}{2 \cdot \text{TP} + \text{FP} + \text{FN}}$$
- Range: $[0, 1]$, where $1.0$ is perfect change segmentation.

#### 4. Intersection-over-Union (IoU / Jaccard Index)
The ratio of the area of overlap between the predicted change and ground truth to the area of union:
$$\text{IoU} = \frac{\text{TP}}{\text{TP} + \text{FP} + \text{FN}} = \frac{F_1}{2 - F_1}$$

---

### 2.3 Mathematical Proof: Why Overall Accuracy (OA) is Misleading
Overall Accuracy is defined as:
$$\text{OA} = \frac{\text{TP} + \text{TN}}{\text{TP} + \text{TN} + \text{FP} + \text{FN}}$$

In our verified LEVIR-CD dataset:
- Total pixels $N_{\text{total}} = 667,942,912$
- Changed pixels $N_{\text{change}} = \text{TP} + \text{FN} = 31,066,643$ ($4.651\%$)
- Non-changed pixels $N_{\text{non-change}} = \text{TN} + \text{FP} = 636,876,269$ ($95.349\%$)

Consider a null/trivial detector $\hat{Y}_0(x, y) = 0 \quad \forall (x, y)$:
$$\text{TP} = 0, \quad \text{FP} = 0, \quad \text{FN} = 31,066,643, \quad \text{TN} = 636,876,269$$
The metrics for this completely useless detector evaluate to:
- $\text{Precision} = 0.000$
- $\text{Recall} = 0.000$
- $F_1 = 0.000$
- $\text{IoU} = 0.000$
- $\mathbf{\text{OA}} = \frac{0 + 636,876,269}{667,942,912} = \mathbf{95.349\%}$

**Conclusion:** A model that detects absolutely nothing achieves $>95\%$ Overall Accuracy. Consequently, OA cannot distinguish between a high-performing model and a trivial null predictor. `[PROJECT DECISION: DEC-016]` forbids using OA as a model selection criterion.

## 3. Leakage-Safe Threshold Selection Policies

Classical methods (B1, B2, B3) generate continuous difference maps $D(x, y) \in [0, 1]$ requiring a threshold $\tau$ to yield binary masks.

### Policy A: Validation-Set Calibrated Threshold ($\tau_{\text{val}}^*$)
To prevent data leakage, the decision threshold is determined strictly on the validation partition ($M = 64$ scenes) and then frozen:
1. Discretize candidate thresholds $\tau \in [0.01, 0.99]$ with step size $\Delta \tau = 0.01$.
2. Compute cumulative $\text{TP}_{\text{val}}(\tau), \text{FP}_{\text{val}}(\tau), \text{FN}_{\text{val}}(\tau)$ over all 64 validation scenes.
3. Select optimal threshold:
   $$\tau^* = \arg\max_{\tau} F_1(\tau; \mathcal{D}_{\text{val}})$$
4. Freeze $\tau^*$ and apply it to the test partition ($M = 128$ scenes):
   $$\hat{Y}_{\text{test}}(x, y) = \mathbb{I}[D_{\text{test}}(x, y) \ge \tau^*]$$
5. Report $F_1, \text{IoU}, P, R$ on the test set with zero parameter tuning on test data.

### Policy B: Unsupervised Scene-Adaptive Otsu Threshold ($\tau_{\text{Otsu}}$)
For fully unsupervised operation without any labeled data:
$$\tau_{\text{Otsu}} = \arg\max_t \sigma_B^2(t)$$
Where between-class variance $\sigma_B^2(t) = \omega_0(t) \omega_1(t) (\mu_0(t) - \mu_1(t))^2$ is computed per-scene or across the validation set histogram.

## 4. Computational Efficiency & Hardware Profiling Metrics

Under strict CPU execution `[PROJECT DECISION: DEC-003]`, every algorithm must be benchmarked using the following standardized protocol:

### 4.1 Timing Protocol
- **Hardware Environment:** Quad/octa-core x86_64 / ARM CPU, $\le 8$ GB RAM budget, no GPU.
- **Warmup Runs:** Exactly 5 warm-up iterations discarded before profiling to ensure instruction cache and JIT stabilization.
- **Measurements:**
  - $\bar{t}$ (Mean Latency): Average execution time across $N$ iterations.
  - $p50$ (Median Latency): 50th percentile wall-clock time.
  - $p95$ (Tail Latency): 95th percentile wall-clock time.
  - Throughput: $\text{Throughput} = \frac{N}{\sum_{i=1}^N t_i} \text{ samples/sec}$.

### 4.2 Memory Protocol
- **Peak Process RSS (Resident Set Size):**
  $$\text{RSS}_{\text{peak}} = \max_t (\text{Process Memory in RAM (MB)})$$
- **Peak Heap Allocation:** Measured via Python `tracemalloc.get_traced_memory()[1] / (1024 \times 1024)`.
- **Model Storage Footprint:** File size of serialized model weights (`.pt`, `.onnx`) on disk in MB.
- **Vector Index Footprint:** File size of FAISS index in MB.

## 5. Controlled Perturbation Robustness Metrics

To measure false-alarm susceptibility under environmental confounders, we define two perturbation metrics:

### 1. Relative F1 Degradation ($\Delta F_1$)
$$\Delta F_1 = \frac{F_1(\text{clean}) - F_1(\text{perturbed})}{F_1(\text{clean})} \times 100\%$$

### 2. False Positive Amplification Factor (FPAF)
Measures the multiplier increase in spurious false-alarm pixels induced by a specific perturbation:
$$\text{FPAF} = \frac{\text{FP}_{\text{perturbed}}}{\text{FP}_{\text{clean}}}$$
- $\text{FPAF} = 1.0$ indicates perfect invariance to the confounder.
- $\text{FPAF} > 2.0$ indicates that the perturbation more than doubled the false alarm rate.
- Models with lower FPAF are demonstrably more robust against non-ground variations.
